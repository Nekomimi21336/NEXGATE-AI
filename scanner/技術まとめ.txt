1. 概要（Abstract）
--------------------------------------------------------------------------------

本システムは、スマートフォンやカメラで撮影された教育教材（教科書・問題集）
の画像から、単一ページを自動分離し、日本語テキストを光学文字認識（OCR）で
抽出し、さらに大規模言語モデル（LLM）により問題の意味構造を復元する
エンドツーエンドのドキュメント理解パイプラインである。

対象ドメインは、選択肢・空欄・並べ替え・図表ラベルなど複雑なレイアウトを
持つ日本語の印刷教材であり、従来の「テキスト列の羅列」にとどまらず、
セクション・設問・選択肢・手順といった論理構造を JSON および Markdown
として出力することを目的とする。

処理は以下の4段階で構成される。

  (1) ページ領域検出・透視補正による単一ページ画像の切り出し
  (2) 日本語特化 OCR による文字検出・認識と座標付きテキスト抽出
  (3) 幾何学的レイアウト解析による読み順整列とヒューリスティック分類
  (4) LLM によるノイズ補正と意味的構造化（オプション）

本書では各段階で用いているアルゴリズム、ライブラリ、設計上の根拠を
論文調に整理する。

2. システムアーキテクチャ
--------------------------------------------------------------------------------

2.1 処理フロー

  入力画像（JPEG/PNG 等）
    │
    ├─► [ページ領域検出] page_region.py
    │     ・色空間セグメンテーション（LAB + Otsu）
    │     ・輪郭近似による四隅推定
    │     ・輝度・彩度に基づく境界精緻化
    │     ・透視変換（ホモグラフィ）によるページ切り出し
    │
    ├─► [OCR] extract_text.py + RapidOCR
    │     ・テキスト検出（Text Detection）
    │     ・方向分類（Text Line Orientation Classification）
    │     ・テキスト認識（Text Recognition, 日本語モデル）
    │
    ├─► [レイアウト後処理] extract_text.py
    │     ・座標に基づく読み順ソート・行結合
    │     ・正規表現による設問タイプのヒューリスティック分類
    │     ・ページ内／ページ外テキストのフィルタリング
    │
    └─► [意味構造化] structure_content.py（--structure 時）
          ・OpenAI 互換 Chat Completions API へのプロンプト送信
          ・JSON スキーマに沿った設問構造の復元
          ・Markdown への人間可読変換

2.2 モジュール構成

  extract_text.py   … メイン CLI、OCR 実行、出力保存
  page_region.py    … ページ四辺検出、透視切り出し、可視化
  structure_content.py … LLM による構造化 API クライアント
  requirements.txt  … 依存ライブラリ定義

2.3 出力成果物

  *.txt              … ページ内 OCR プレーンテキスト
  *.json             … OCR 座標・ページ領域・メタデータ
  *_page.jpg         … 透視補正済み単一ページ画像
  *_page_region.png  … 四辺境界・色マスクの可視化
  *_output.png       … OCR バウンディングボックス可視化
  *_structured.json  … LLM 構造化結果（JSON）
  *_structured.md    … LLM 構造化結果（Markdown）

3. 光学文字認識（OCR）サブシステム
--------------------------------------------------------------------------------

3.1 基盤技術: RapidOCR / PaddleOCR 系 ONNX モデル

本システムの OCR エンジンには RapidOCR（Python パッケージ rapidocr）を
採用する。RapidOCR は Baidu の PaddleOCR で学習されたモデルを ONNX 形式に
変換し、ONNX Runtime 上で推論する軽量 OCR フレームワークである。

参照: RapidOCR プロジェクト（https://github.com/RapidAI/RapidOCR）
参照: PaddleOCR（Du et al., PP-OCR シリーズ, arXiv 系技術報告）

3.2 三段構成パイプライン

  (A) テキスト検出（Text Detection）
      モデル: PP-OCRv6 系検出モデル（本実装では det_small.onnx）
      手法: Differentiable Binarization（DB）に基づくテキスト領域検出
      出力: 各テキスト行を囲む四辺形（ポリゴン）座標

  (B) テキスト行方向分類（Text Line Orientation Classification）
      モデル: ch_ppocr_mobile_v2.0_cls
      目的: 180度回転した行の補正（0° / 180° 分類）

  (C) テキスト認識（Text Recognition）
      モデル: japan_PP-OCRv4_rec_mobile（日本語辞書付き）
      手法: CRNN / SVTR 系のシーケンス認識
      出力: 文字列と信頼度スコア

日本語教材に対して中国語汎用認識モデル（ch_PP-OCR）ではなく
japan_PP-OCRv4 を明示的に指定することで、漢字・かな混在文の
誤認識（例: 「顕微鏡」→「頭微镜」）を大幅に低減している。

3.3 推論ランタイム

  ONNX Runtime（CPU）をバックエンドとする。
  GPU 非依存であり、ローカル PC・サーバ双方で再現可能な構成とした。

3.4 OCR 後処理

  (1) 信頼度フィルタ（min_score, デフォルト 0.45）
  (2) 読み順整列: バウンディングボックスの上端 y 座標、次いで左端 x 座標で
      ソート
  (3) 行結合: 近接する y 座標（閾値 16px）かつ x 方向ギャップ（閾値 70px）
      以内のボックスを同一行として結合
  (4) 正規表現による誤認識補正テーブル（例: 国1→知1, 図1→知1, (口)→(1)）

3.5 オプション前処理

  --preprocess 指定時:
    ・解像度の短辺を 2000px 以上に拡大（双三次補間）
    ・LAB 色空間の L チャンネルに CLAHE（Contrast Limited Adaptive
      Histogram Equalization）を適用し、照明むらを低減

  デフォルトでは前処理を無効化。実験の結果、日本語モデル単体の方が
  過度な前処理より安定するケースが多かったためである。

4. ページ領域検出・単一ページ切り出し
--------------------------------------------------------------------------------

4.1 課題設定

撮影画像には、対象ページ以外に以下が混入しうる。

  ・隣接ページ（見開きの右ページ、上下の次ページ）
  ・背景（机、キーボード等の低輝度領域）
  ・のど（製本の赤色マージン）

OCR だけでは「どの画素が対象ページか」を幾何的に切り分けられないため、
ページ領域検出モジュールを独立させた。

4.2 色に基づく紙領域セグメンテーション

  色空間: CIELAB の L（輝度）チャンネル
  二値化: Otsu の自動閾値法（THRESH_BINARY + THRESH_OTSU）
  理由: 白紙は背景（暗部）と輝度ヒストグラム上で二峰性を示しやすく、
        教師なしで紙領域マスクを得られる

  形態学処理:
    ・クロージング（21×21 矩形カーネル, 4 回）… 紙内の小穴を埋める
    ・オープニング（2 回）… 孤立ノイズ除去

  最大連結成分の輪郭を取得し、Douglas-Peucker 近似（epsilon = 1.5% 周長）
  により四辺形に簡略化する。4 点未満の場合は minAreaRect による代替を用いる。

4.3 文書座標系と角度推定

  OCR で得られた横長テキスト行（幅/高さ ≥ 2.5, 4 文字以上）から
  文書の読み方向（角度 θ）を推定する。

  手法:
    ・最長テキスト行の上辺ベクトルから基準角を取得
    ・上位 5 本（または全体の 1/4）の長い行について幅加重円平均
    ・180° 曖昧性は align_angle により解消

  色ベース四隅と OCR 角度を統合（color+ocr モード）:
    weighted_angle([θ_color, θ_ocr], [2.0, 1.0])

  原点は横長行群の中心座標のメディアンとする。

4.4 境界の精緻化

  右端・左端について、文書座標系上で輝度・彩度プロファイルを走査する。

  右端精緻化:
    ・外側から内側へサンプリング
    ・L < 150 または HSV 彩度 S > 80 で紙/非紙境界と判定
    ・背景や赤のどの混入を抑制

  上下端は色マスク四辺形の範囲を基本とし、軽微なマージン（高さの 1.5%）を付与。

4.5 透視変換によるページ切り出し

  検出四隅（TL, TR, BR, BL）から出力解像度を算出し、
  cv2.getPerspectiveTransform / cv2.warpPerspective により
  矩形化した単一ページ画像（*_page.jpg）を生成する。

  これにより、撮影時の傾き・台形歪みを補正し、後段 OCR の安定性を向上させる。

4.6 ページ内テキストフィルタ

  各 OCR ボックスの中心点が四辺形ポリゴン内にあるかを
  cv2.pointPolygonTest により判定し、ページ外テキストを excluded として分離する。


--------------------------------------------------------------------------------
5. レイアウト解析・ヒューリスティック構造化
--------------------------------------------------------------------------------

5.1 設問タイプ分類（正規表現ベース）

  OCR 行に対し、以下のパターンでブロック種別を付与する（extract_text.py）。

    section        … 知1, 図1 等のセクション見出し
    question       … (1), (2) 等の設問番号
    choice         … (a), (ア) 等の選択肢
    option         … 「の対物レンズ」形式の部品リスト
    step           … ①②③ の手順文
    instruction    … 「選べ」「答えよ」「並べ」等の指示語
    blank          … 括弧・空欄のみの行

  本層は LLM なしでも動作する軽量な構造化であり、JSON の sections フィールド
  に格納される。精度は OCR 品質に強く依存する。

5.2 座標メタデータ

  各 OCR 項目に以下を付与する。

    index    … 検出行の通し番号
    box      … 四隅ポリゴン座標（ピクセル）
    center   … 重心座標
    score    … 認識信頼度
    in_page  … ページ四辺形内か否か

6. 大規模言語モデル（LLM）による意味構造化
--------------------------------------------------------------------------------

6.1 動機

  OCR 出力は誤認識・行分割の乱れ・図表ラベルの混在などにより、
  人間が読む教材としては不完全である。ルールベースだけでは
  「知1 の中の (1) と (2) の関係」「並べ替え問題の 7 手順」等の
  意味的階層を安定して復元できない。

  そこで LLM を後段に配置し、文脈に基づく誤字補正とスキーマ拘束付き
  構造化を行う（structure_content.py）。

6.2 API 仕様

  プロトコル: OpenAI Chat Completions API 互換
  エンドポイント: https://api.nexgate.space/v1/chat/completions
  認証: Bearer トークン（環境変数 NEXGATE_API_TOKEN）
  デフォルトモデル: nexgate-base
  応答形式: response_format = {"type": "json_object"}

6.3 プロンプト設計

  System プロンプト:
    ・日本の教科書 OCR 整理専用
    ・推測による問題の作り足し禁止
    ・JSON のみ返却

  User プロンプトに含める情報:
    (1) OCR 生テキスト全文
    (2) 行番号付き OCR 項目リスト（in_page のみ）
    (3) 出力 JSON スキーマ（title, summary, sections[].questions[]）

  設問 type の分類体系:
    matching              … 図の部品名選択
    matching_description  … 説明文と部品の対応
    ordering              … 手順の並べ替え
    multiple_choice       … a,b,c から選ぶ
    short_answer          … 数値・記述解答

6.4 応答パース

  ・response_format による JSON 生成を基本とする
  ・制御文字混入時は正規表現でサニタイズ後に json.loads
  ・コードフェンス ```json ... ``` の除去に対応

6.5 出力

  *_structured.json … 機械処理用
  *_structured.md   … 人間レビュー用（structured_to_markdown）

8. 評価観点と既知の限界
--------------------------------------------------------------------------------

8.1 本手法の長所

  ・日本語特化 OCR モデルにより教育漢字の認識精度が実用域に達する
  ・色セグメンテーションと透視変換により「1ページだけ」を切り出せる
  ・座標付き JSON により UI へのマッピング（ハイライト、空欄検出）が可能
  ・LLM 後段により OCR ノイズを吸収し、設問スキーマへ復元できる

8.2 既知の限界

  (1) ページ検出
      ・紙と背景の輝度差が小さい場合、Otsu 分割が失敗しうる
      ・赤のどは紙と同様に明るく検出され、右端が広がることがある
      ・上下方向の「次ページ混入」は左右境界だけでは完全には除去できない

  (2) OCR
      ・図中の小ラベル、(ア)(イ) 等の記号は誤認識しやすい
      ・空欄「[]」は形状として検出されにくい
      ・手書き答案には未対応（印刷体前提）

  (3) LLM 構造化
      ・API 依存・レイテンシ（数十秒級）・コストが発生
      ・幻覚（hallucination）のリスクがあり、プロンプトで抑制しているが
        ゼロではない
      ・教科書単元ごとにプロンプトを一般化する必要がある

8.3 今後の拡張方向（研究・開発）

  ・Document Layout Analysis（LayoutLM, DocTr 等）の導入
  ・空欄・チェックボックス検出のための専用オブジェクト検出
  ・複数ページのバッチ処理とページ番号推定
  ・LLM 出力のスキーマ検証（JSON Schema / Pydantic）
  ・ローカル LLM によるオフライン構造化
  ・Ground Truth との定量評価（CER, WER, 構造 F1）

10. 実行方法（技術者向けクイックリファレンス）
--------------------------------------------------------------------------------

  基本 OCR + ページ切り出し:
    python extract_text.py

  AI 構造化を含む完全パイプライン:
    set NEXGATE_API_TOKEN=ngx_...
    python extract_text.py --structure

  主要オプション:
    --preprocess       … CLAHE + 拡大前処理
    --page-margin 0.08 … ページ幅に対する余白比率
    --no-page-filter   … ページ内フィルタ無効
    --no-vis           … 可視化 PNG 出力を抑制
    --structure        … LLM 構造化を有効化
    --api-model        … モデル ID 指定（nexgate-base 等）


--------------------------------------------------------------------------------
11. 結語
--------------------------------------------------------------------------------

本プロジェクトは、古典的なコンピュータビジョン（閾値処理・輪郭検出・
透視変換）、深層学習ベース OCR（PP-OCR / ONNX）、幾何学的レイアウト解析、
および生成 AI（LLM によるスキーマ拘束 JSON 生成）を段階的に結合した
ハイブリッド型ドキュメント理解パイプラインである。

教育現場で撮影された非構造画像を、単一ページの構造化されたデジタル教材表現へ
変換するという実問題に対し、各層が独立モジュールとして分離されており、
OCR のみ、ページ切り出しのみ、LLM 構造化のみといった部分利用も可能な設計と
なっている。
